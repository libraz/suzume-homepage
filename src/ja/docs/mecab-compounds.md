# 複合語・数量・名前

Suzume は複合語や数量を一つの検索単位にまとめる一方、生産的な接尾辞や行政区分の境界は残します。ここでは、語句の種類ごとに結合と分割を並べて説明します。

比較条件と読み方は [MeCab との違い](/ja/docs/mecab-comparison#比較条件)、品詞の付け方は [POS 分類の違い](/ja/docs/pos-differences)を参照してください。

## 複合語

### 漢字複合語

辞書や文法規則から内部境界を判断できない未登録の漢字列は、通常1つの名詞候補として保持します。一方で `神奈川県 / 横浜市` や `会議 / 中` のような構造上の境界は分割します。

<TokenDiff
  input="経済成長"
  mecab="経済(名詞) / 成長(名詞)"
  suzume="経済成長(NOUN)"
/>

<TokenDiff
  input="開始予定"
  mecab="開始(名詞) / 予定(名詞)"
  suzume="開始予定(NOUN)"
/>

<Why>

完全な辞書がなければ、漢字複合語のどこで分割すべきか判断できません。結合するほうが安全な選択です — 過剰に結合されたトークンでも、テキスト範囲は正確に捕捉されます。特定の分割が必要な場合はユーザー辞書で定義できます。

</Why>

### カタカナ複合語

未知の一般的なカタカナ列は、通常1つの名詞候補として保持します。辞書や形状規則に根拠があれば、「ドキドキ（ADV）」のように別の品詞を付与します。

<TokenDiff
  input="サンプルデータ"
  mecab="サンプル(名詞) / データ(名詞)"
  suzume="サンプルデータ(NOUN)"
/>

<TokenDiff
  input="セットリスト"
  mecab="セット(名詞) / リスト(名詞)"
  suzume="セットリスト(NOUN)"
/>

<Why>

辞書や構造上の根拠がなければ、カタカナ列の分割は不確実です。名詞候補は既定の候補であり、辞書候補や擬態語候補とも比較されます。

</Why>

### 文字種をまたぐ複合語

英字語に続くカタカナ語は1つの複合名詞になります。

<TokenDiff input="AIブーム" mecab="AI / ブーム" suzume="AIブーム(NOUN)" />

### 動詞連用形からの複合名詞

動詞の連用形＋「会」、および行き先を表す「行き」は、1つの名詞になります。

<TokenDiff input="飲み会" mecab="飲み / 会" suzume="飲み会(NOUN)" />

<TokenDiff input="東京行き" mecab="東京 / 行き" suzume="東京行き(NOUN)" />

複合動詞の連用形を名詞として使う場合、後続する名詞とは分かれることがあります。`取り扱い方法` は `取り扱い(NOUN) / 方法(NOUN)` になります。

<Why>

実際に検索される単位は「飲み会」「東京行き」です。この文脈では「飲み」「行き」の動詞由来であることに単独の価値はありません。

</Why>

### 名詞＋一字接尾辞

次の限定された名詞＋一字接尾辞の組み合わせを結合します。

<TokenDiff input="報告書" mecab="報告 / 書" suzume="報告書(NOUN)" />

<TokenDiff input="成功率" mecab="成功 / 率" suzume="成功率(NOUN)" />

対象接尾辞: 書、誌、時、率、性

<Why>

これらの名詞＋接尾辞の組み合わせは単一の語彙として機能します。

</Why>

### 動詞連用形＋「方」

短い動詞連用形に形式名詞「方」が続く場合、方法を表す単一の検索単位に結合します。

<TokenDiff input="走り方" mecab="走り / 方" suzume="走り方(NOUN)" />

結合するのは短い語幹だけです。連用形が2文字以内の場合に限られます（走り方、やり方）。長い連用形は境界を維持し、「打ち合わせ方」は「打ち合わせ / 方」のままです。長い連用形転成名詞の後でも同じ境界を保ち、`取り扱い方` は `取り扱い(NOUN) / 方(SUFFIX)` になります。

<Why>

「〜方」は動作方法を表す語彙的な検索単位であり、動詞語幹と一緒に扱う方が検索に適しています。

</Why>

## 数量と日付

### 数字と単位

基数に助数詞・単位が続く場合は、通常1つの数量トークンに結合します。大きな数値単位（万、億、兆）、小数、パーセント、アルファベット単位にも対応します。ただし序数や構造接尾辞の規則により、`第三 / 回` のように分割する場合があります。

<TokenDiff input="3人" mecab="3 / 人" suzume="3人(NOUN)" />

<TokenDiff input="100円" mecab="100 / 円" suzume="100円(NOUN)" />

<TokenDiff input="3.14" mecab="3 / . / 14" suzume="3.14(NOUN)" />

数量の前後には検索単位としての境界を維持します。

<TokenDiff input="徒歩五分" mecab="徒歩 / 五 / 分" suzume="徒歩 / 五分(NOUN)" />

<TokenDiff input="三ヶ月間入院" mecab="三 / ヶ月 / 間 / 入院" suzume="三ヶ月間(NOUN) / 入院" />

`3種類`、`3人分`、`3ページ目` のような数量表現も、全体を 1 つの `NOUN` トークンとして保持します。助数詞の認識で後続の語を途中で切らず、数量に続く「分」や順序を表す「目」も数量の一部として扱います。

カンマで桁を区切った数値は、数値全体を一語として扱います。後続する助数詞は独立した `SUFFIX` にし、金額は一つの検索単位にまとめます。

<TokenDiff input="1,000人" mecab="1 / , / 000 / 人" suzume="1,000(NOUN) / 人(SUFFIX)" />

<TokenDiff input="1,000円" mecab="1 / , / 000 / 円" suzume="1,000円(NOUN)" />

同じ結合はアラビア数字以外にも適用されます。

**かな表記の数量:**

<TokenDiff input="よんにん" mecab="よ(形容詞) / ん(名詞) / に(助詞) / ん(助詞)" suzume="よんにん(NOUN)" />

**配分表現の数量:**

<TokenDiff input="一語一語" mecab="一語(名詞) / 一(名詞) / 語(名詞)" suzume="一語一語(NOUN)" />

**番地・地番:**

<TokenDiff input="1-2-3" mecab="1 / - / 2 / - / 3" suzume="1-2-3(NOUN)" />

**序数の「第」と概数の「約」:** 序数接頭辞の「第」は数字と結合し、後続の助数詞は独立した `SUFFIX` トークンになります。概数接頭辞の「約」は逆に独立した `PREFIX` のまま、数字が助数詞と結合します。

<TokenDiff input="第三回" mecab="第 / 三 / 回" suzume="第三(NOUN) / 回(SUFFIX)" />

<TokenDiff input="約三人" mecab="約 / 三 / 人" suzume="約(PREFIX) / 三人(NOUN)" />

<Why>

多くのアプリケーション（検索、タグ付け、表示）では、「3人」や「三ヶ月間」を1つの単位として扱い、前後の名詞から分離する方が有用です。

</Why>

### 日付

完全な日付表現は単一トークンに結合されます。

<TokenDiff
  input="2024年12月23日"
  mecab="2024 / 年 / 12 / 月 / 23 / 日"
  suzume="2024年12月23日(NOUN)"
/>

<Why>

日付は意味の原子単位です。分割しても実用的なメリットはありません。

</Why>

## 名前と接尾辞

### 固有名詞と地名

地名構成要素と地域接尾辞の多くは結合します。ただし `県+市` は構造規則による例外で、都道府県と市を分割します。

<TokenDiff input="東京都新宿区" mecab="東京 / 都 / 新宿 / 区" suzume="東京都新宿区(NOUN)" note="place name" noteJa="地名" />

<Why>

複数の地理的要素からなる地名は、検索や表示において単一のエンティティとして扱うべきです。

</Why>

### 県＋市

県＋市の複合名詞は行政区画の境界で分割されます。

<TokenDiff input="神奈川県横浜市" mecab="神奈川 / 県 / 横浜 / 市" suzume="神奈川県 / 横浜市" note="split at the 県 / 市 boundary" noteJa="県／市の境界で分割" />

注: この分割ルールは `県+市` パターンにのみ適用されます。`都+区`（東京都新宿区）や `府+市`（大阪府大阪市）などの組み合わせは、[固有名詞と地名](#固有名詞と地名)の結合ルールにより単一トークンに結合されます。

<Why>

県と市は異なる行政レベルであり、境界の分割は検索やジオコーディングにおいて有用です。

</Why>

### 敬称とひらがな愛称

敬称は名前から分割されます。

対象敬称: さん、ちゃん、くん、様、さま。漢字表記の「君」「殿」は、2字以上の漢字からなる語の後では分割します（`佐藤 / 君`、`先生 / 殿`）。

これらの敬称でも、公開 API の品詞は一律ではありません。`佐藤様` は `佐藤(NOUN) / 様(NOUN)` になります。

<TokenDiff input="佐藤君" mecab="佐藤(名詞・固有名詞) / 君(名詞・接尾)" suzume="佐藤(NOUN) / 君(SUFFIX)" />

漢字1字の後では、人名と「主君」のような普通の複合語を区別できません。そのため `林君` は一語のままです。これは語彙情報がないことによる制約です。

<TokenDiff input="林君" mecab="林(名詞・固有名詞) / 君(名詞・接尾)" suzume="林君(NOUN)" />

例外: お兄ちゃん、お母さんなどの家族語と、「皆様」「皆さん」は単一トークンとして維持されます。

2〜3文字のひらがな語幹に「ちゃん」「くん」が続く短い愛称や、辞書化された家族語は検索単位として結合する場合があります。通常の「さん」は、漢字の名前に付く場合も独立した接尾辞になります。

<TokenDiff input="わんちゃん" mecab="わん / ちゃん" suzume="わんちゃん(NOUN)" />

<Why>

通常の名前は敬称を分離する方が検索や表示に有用ですが、短いひらがな愛称は全体が検索対象になります。

</Why>

### 動詞連用形＋生産的接尾辞

動詞語幹に付く生産的な接尾辞 — がち（傾向）、たて（直後）、っぱなし（放置） — は境界を維持して `SUFFIX` を付与するため、動詞語幹は原形付きで検索可能なままです。

<TokenDiff input="忘れがち" mecab="忘れ(動詞) / がち(名詞・接尾)" suzume="忘れ(VERB, lemma: 忘れる) / がち(SUFFIX)" />

<TokenDiff input="できたて" mecab="でき(動詞) / た(助動詞) / て(助詞)" suzume="でき(VERB, lemma: できる) / たて(SUFFIX)" />

<TokenDiff input="開けっぱなし" mecab="開けっぱなし(名詞)" suzume="開け(VERB, lemma: 開ける) / っぱなし(SUFFIX)" />

否定構文の「読みっこない」も同じ方針で、読み（`VERB`）/ っこ（`SUFFIX`）/ ない（`ADJ`）に分かれます。

### 数量・状態の接尾辞

Suzume は漢字複合語を積極的に結合しますが、生産的な数量・状態の接尾辞は境界を維持して `SUFFIX` を付与します。

<TokenDiff input="二階建て" mecab="二 / 階 / 建て" suzume="二階(NOUN) / 建て(SUFFIX)" />

<TokenDiff input="砂糖抜き" mecab="砂糖(名詞) / 抜き(名詞)" suzume="砂糖(NOUN) / 抜き(SUFFIX)" />

<TokenDiff input="会議中に" mecab="会議(名詞) / 中(名詞) / に(助詞)" suzume="会議(NOUN) / 中(SUFFIX) / に(PARTICLE)" />

「例年並み」は `例年(NOUN) / 並み(SUFFIX)`、「汗まじり」は `汗(NOUN) / まじり(SUFFIX)` に分かれます。「中」は前の語によって役割が変わり、形容詞が修飾する「忙しい中」は `忙しい(ADJ) / 中(NOUN)` として、「中」を接尾辞ではなく形式名詞にします。

名詞化の「さ」のように境界を変えずにラベルだけ変わる接尾辞は、[POS 分類の違い](/ja/docs/pos-differences)で扱います。

<Why>

「二階建て」に境界がなければ数量が埋もれ、「会議中」を1つの名詞に結合すると「会議」が検索から隠れます。接尾辞はテキスト範囲としては隣接したまま、独立したトークンとして見えるようになります。

</Why>
