# 表記・技術テキスト

語の境界は表記によっても変わります。ひらがなの日常語、長音を使った表現、識別子、記号などの扱いを説明します。

比較条件と読み方は [MeCab との違い](/ja/docs/mecab-comparison#比較条件)、品詞の付け方は [POS 分類の違い](/ja/docs/pos-differences)を参照してください。

## 日常語と口語表現

### ひらがなの日常語

ひらがな表記が一般的な日常語は、パターン規則と小さな L2 辞書を組み合わせて一語のまま扱います。パターン規則は「おととい」「ひこうき」「みっつ」や「翌営業日」のような暦の複合語を処理します。「みず」「てがみ」「ひらがな」「にわ」「いりぐち」「はにわ」「あけぼの」「くだもの」のように、助詞や活用語尾と同じ文字を含む曖昧な名詞には辞書の語彙情報を使います。

### スラング・現代語

現代の口語的な形容詞・動詞をネイティブに認識します。

<TokenDiff input="エモい" mecab="エモ(名詞) / い(動詞)" suzume="エモい(ADJ)" />

認識例: エモい、キモい、ウザい、ダサい、イタい、ヤバい、複合イ形容詞。ひらがな表記の認識には文脈が必要な場合があります。`頭がいたい` は `頭(NOUN) / が(PARTICLE) / いたい(ADJ)` になりますが、単独の `いたい` は `い(VERB) / たい(AUX)` になります。

動詞の認識例: バズる、ググる、パクる

<Why>

比較に使う IPADIC には「ダサい」など一部の口語語彙がありますが、新しい語彙の多くは未収録です。Suzume は選択したスラングパターンと、その活用形（エモかった、バズった、ググった等）を認識します。

</Why>

### ナイ形容詞

「ない」で終わる特定の形容詞は、分割せず単一の語彙として扱います。

<TokenDiff input="だらしない" mecab="だらし(名詞・ナイ形容詞語幹) / ない(助動詞)" suzume="だらしない(ADJ)" />

単一語として処理する主な例: だらしない、つまらない、もったいない、くだらない、いたたまれない、ものたりない、こころもとない

これは閉じた語彙リストです。生産的な「語幹＋ない」の組み合わせは分割します — [生産的な否定の分割](/ja/docs/mecab-grammar#生産的な否定の分割)を参照してください。

<Why>

これらの語は現代日本語で不可分の形容詞として機能します。「語幹＋ない」の分割は語源的には正しいですが、NLP アプリケーションでは有用ではありません。

</Why>

### 長音記号

長音記号（ー）は前のトークンに結合されます。認識した口語のイ形容詞では、表層形の長音記号を保持しつつ、原形を通常の辞書形に正規化します。

<TokenDiff input="そうー" mecab="そう(副詞) / ー(名詞)" suzume="そうー(ADV)" />

<TokenDiff input="すごーーい" mecab="すご(形容詞) / ーー(名詞) / い(名詞)" suzume="すごーーい(ADJ, lemma: すごい)" />

<Why>

長音は修飾する語の一部です。表層形には入力された長音を残し、原形には口語的な引き伸ばしを含まない形容詞の辞書形を使います。

</Why>

漢字の形容詞語幹でも強調表記を保ちます。「高ーい」と、語尾を切った「高っ」は、それぞれ原形「高い」の `ADJ` です。語中の強調の「っ」が原形に残る場合もあり、「すっごい」は原形も「すっごい」の `ADJ` になります。

助詞末尾の小書き母音は助詞に残し、「のにぃ」は原形「のに」の `PARTICLE` とします。語尾を切った挨拶の「ありがとっ」は、原形「ありがとう」の `INTJ` です。

### 口語の強調助詞

口語の強調助詞は、断片化させずに1つの単位として分割します。

**ったら題目助詞:**

<TokenDiff input="あなたったら" mecab="あな(名詞) / たっ(動詞) / たら(助動詞)" suzume="あなた(PRON) / ったら(PARTICLE)" />

**ってば強調助詞:**

<TokenDiff input="もうってば" mecab="も(助詞) / うっ(動詞) / て(助詞) / ば(助詞)" suzume="もう(ADV) / ってば(PARTICLE)" />

### 定型あいづちの分解

フィラーとして語彙化された定型の会話フレーズは、文法要素に分解します。

<TokenDiff input="そうですね" mecab="そうですね(フィラー)" suzume="そう(ADV) / です(AUX) / ね(PARTICLE)" />

<Why>

1つの不透明なフィラーのままでは内部構造が見えません。分解することで、他の箇所と同じコピュラ・助詞の扱いが適用されます。

</Why>

## 技術的な表記

### テクニカルテキスト

技術的な識別子は単一トークンに結合されます。

**snake_case識別子:**

<TokenDiff input="user_name" mecab="user / _ / name" suzume="user_name" />

**バージョン番号:**

<TokenDiff input="v1.2.3" mecab="v / 1 / . / 2 / . / 3" suzume="v1.2.3" />

**ASCII名＋番号:**

<TokenDiff input="Model15" mecab="Model / 15" suzume="Model15" />

**ASCIIドット記法:**

<TokenDiff input="console.log" mecab="console / . / log" suzume="console.log" />

**ASCII 語中の区切り記号:**

<TokenDiff input="data-driven" mecab="data / - / driven" suzume="data-driven" />

ASCII の単語文字に挟まれたアポストロフィ、アンパサンド、スラッシュも同じ規則で 1 トークンに保ちます。

<Why>

これらは技術テキストにおける不可分な識別子です。分割するメリットはありません。

</Why>

### URL・メンション・ハッシュタグ

URL、@メンション、#ハッシュタグは単一トークンに結合されます。ハッシュタグの走査は、助詞のように見えるひらがなを含む日本語を受け付け、空白または句読点で停止します。

<TokenDiff
  input="https://example.com にアクセス"
  mecab="https / :// / example / . / com / に / アクセス"
  suzume="https://example.com / に / アクセス"
/>

<TokenDiff
  input="@user_name に送信"
  mecab="@ / user / _ / name / に / 送信"
  suzume="@user_name / に / 送信"
/>

<TokenDiff
  input="#topicについて"
  mecab="# / topic / について"
  suzume="#topicについて(NOUN)"
/>

<TokenDiff
  input="#日本語タグ"
  mecab="# / 日本語 / タグ"
  suzume="#日本語タグ(NOUN)"
/>

<Why>

URL、メンション、ハッシュタグは不可分な識別子として扱います。ハッシュタグは文字種と後続の空白・句読点で境界が決まるため、`#topicについて` は 1 つの名詞トークンになります。

</Why>

## 記号と句読点

### 内容を持つ記号と句読点

通貨・単位記号、矢印、数学・技術記号、絵文字は、既定の出力でも `OTHER` として残ります。これらはテキストの内容を持つため、対応する文字範囲もトークンのオフセットに含まれます。句読点などは `SYMBOL` として扱い、既定では省略します。出力に残すには `preserveSymbols` を有効にします。

| オプション | `価格は€50🎉。` |
|-----------|------------------|
| 既定 | `価格(NOUN) / は(PARTICLE) / €(OTHER) / 50(NOUN) / 🎉(OTHER)` |
| `preserveSymbols: true` | `価格(NOUN) / は(PARTICLE) / €(OTHER) / 50(NOUN) / 🎉(OTHER) / 。(SYMBOL)` |
